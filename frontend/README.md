# Brain Tree 🌳

基于树形结构的 LLM 交互对话系统，通过无限画布组织对话结构，支持多角度探索和智能上下文管理。

## ✨ 核心特性

- **🌳 树形对话结构** - 将线性对话转换为树形结构，支持从同一前置信息进行多角度探索
- **🎨 无限画布** - 基于ReactFlow的无限画布，自由组织对话节点
- **🔗 可视化连线** - 紫色流动箭头展示节点关系，清晰呈现上下文传递
- **🧠 智能上下文** - 自动构建完整对话链，AI理解历史信息，回答更连贯
- **💬 多画布管理** - 每个画布对应独立对话空间，支持多主题并行
- **📝 智能卡片展示** - AI自动生成主题和概述，快速浏览对话内容
- **⚡ 即时显示** - 点击卡片立即查看完整内容，无需等待
- **✏️ 完全可编辑** - 手动连接/断开节点，自由重组对话结构
- **🎯 循环检测** - 自动防止循环引用，保护数据完整性
- **📱 现代化UI** - 毛玻璃效果、大圆角、悬浮式布局、精美动画

## 📖 使用指南

### 第一次对话（30秒）

1. **点击** "✨ 创建对话空间" 按钮
2. **点击** 底部工具栏的 "💬 Dialogue" 按钮
3. **输入** 你的问题，例如 "什么是React?"
4. **勾选** "连接LLM自动回答"
5. **点击** "创建" 或按 Enter

AI会自动生成：
- **对话主题**：8-15字的简洁标题
- **对话概述**：20-40字的简短摘要
- **完整回答**：详细的答案内容

### 查看对话

- **卡片视图**：在画布上直接显示主题和概述
- **详细视图**：点击卡片打开模态窗口，查看完整的问题和AI回答
- **即时显示**：内容立即呈现，无需等待
- **Markdown渲染**：支持代码高亮、表格等格式

### 创建对话分支

1. 将鼠标悬停在对话卡片上
2. 点击 **➕** 按钮添加子对话（基于父对话的上下文）
3. 点击 **🗑️** 按钮删除对话
4. 对话节点通过紫色箭头连线，形成思维导图结构

### 上下文系统

Brain-Tree通过**树形结构**和**可视化连线**智能管理对话上下文：

```
什么是React?
├─ 它的虚拟DOM是如何工作的?    ← AI知道"它"指React
├─ React Hooks有哪些?
└─ React性能如何优化?
```

**核心特点**：
- **自动传递**：子节点自动继承父节点的完整历史
- **可视连线**：紫色流动箭头表示上下文流向
- **节省存储**：每个节点只保存自己的消息，通过树结构动态重建上下文
- **智能理解**：AI理解完整对话链，不需要重复背景信息

### 编辑连线

#### 手动创建连接
1. 将鼠标移到源节点边缘
2. 看到紫色连接点
3. 点击并拖拽到目标节点
4. 释放完成连接

#### 断开连接
1. 点击连线（连线变粗）
2. 按 **Delete** 或 **Backspace** 键
3. 连接断开，上下文链断开

#### 循环检测
系统自动防止循环引用，如果尝试创建循环连接会显示警告。

### 管理画布

- **切换画布**：点击左侧侧边栏的画布列表
- **新建画布**：点击侧边栏底部的"新建对话空间"
- **删除画布**：悬停在画布项上，点击删除图标
- **侧边栏控制**：鼠标移到左边缘展开，移开自动收起

### 画布操作

- **拖拽节点**：移动节点位置，连线自动跟随
- **滚轮缩放**：查看全局或细节
- **拖拽背景**：移动视图
- **网格对齐**：节点自动对齐到网格

## 🎨 核心设计

### 问题解决

传统对话系统采用线性结构，导致：
- ❌ 上下文混乱
- ❌ 无法并行探索多个方向
- ❌ 难以回溯和对比不同答案

Brain-Tree通过树形结构解决这些问题：
- ✅ 每个对话节点独立存在
- ✅ 可从任意节点发起新对话
- ✅ 自然管理上下文关系
- ✅ 可视化连线展示关系

### AI结构化响应

系统使用精心设计的System Prompt引导AI返回结构化数据：

```json
{
  "title": "对话主题（8-15字）",
  "summary": "对话概述（20-40字）",
  "answer": "完整的详细回答"
}
```

优势：
- **快速浏览**：卡片上只显示主题和概述，一目了然
- **节省空间**：画布不会被长文本占满
- **提升效率**：快速定位感兴趣的对话，再展开查看
- **美观统一**：所有卡片保持一致的信息密度

### 上下文管理

#### 动态重建
每个节点只保存自己的消息，通过树形结构动态重建完整上下文：

```typescript
// 节点1：[问题1, 回答1]
// 节点2：[问题2, 回答2]  ← 通过parentId找到节点1
// 节点3：[问题3, 回答3]  ← 通过parentId找到节点2

// 创建子节点时：
完整上下文 = [
  节点1的messages,
  节点2的messages,
  节点3的messages,  // 当前节点
]
```

#### 性能优化
- **存储效率**：节省50%存储空间
- **按需计算**：只在需要时构建上下文
- **缓存策略**：未来可实现智能缓存

## 💡 使用技巧

### ✅ 推荐做法

**清晰的问题**：
- ✅ "React的useEffect如何清理副作用?"
- ❌ "React问题"

**利用上下文**：
- ✅ 父节点："什么是React?"
- ✅ 子节点："它和Vue有什么区别?" （AI知道"它"指React）

**并行探索**：
```
根问题
├─ 方案A
├─ 方案B
└─ 方案C
```

**合理的分支深度**：
- 建议不超过5层
- 过深会导致上下文过长

### ❌ 避免做法

**过深的嵌套**：
```
根 → 1 → 2 → 3 → 4 → 5  ❌ 太深了
```

**重复背景信息**：
- ❌ 每次都说"我在用React开发..."
- ✅ 利用上下文，AI会记住

## ❓ 常见问题

**Q: 看不到连线？**  
A: 确保创建了子节点（点击卡片上的➕按钮），连线会自动生成。

**Q: AI回答不连贯？**  
A: 检查是否有父节点连线（紫色箭头），这决定了上下文传递。

**Q: 卡片显示不完整？**  
A: 卡片只显示主题和概述，点击卡片查看完整内容。

**Q: API密钥无效？**  
A: 检查 `config.ts` 文件是否存在，API密钥是否正确，网络是否能访问API地址。
